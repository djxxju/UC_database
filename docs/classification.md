# 算例分类

在根 README 和 [catalog.json](../catalog.json) 按**节点数 → 机组记录数 → 数据完备度**组织算例。每例保留原有 `case_id`、`family`、profile、来源及分发版本。正式文件仍按 `cases/<case_id>`、`reports/<case_id>`、`results/<case_id>` 存放。

1. 节点数按来源已核记录排序。明确单母线表示列为 1 节点。当前资料仅给出系统总负荷时，节点信息单列为未提供。
2. 同一节点类别按机组原记录数排序。算例 README 另列聚合机组、调相机、储能、零有功记录等资源。原记录数与可正出力设备数分别登记。
3. 相同节点数及机组记录数时，按数据完备度 A 至 D 排列，待审排在最后。等级范围、证据和日期见索引中的 `data_completeness` 及算例 README。

| 等级 | 判定依据 |
| --- | --- |
| A 参数与规则齐备 | 所声明 profile 的适用参数、单位、时间轴、成本和初末边界均有证据，适用缺口已闭合。 |
| B 明确简化型 | 来源明确采用简化模型，声明的简化范围内参数和规则齐备。逐项列出明确采用的单节点、单档启动、显式零备用等简化。 |
| C 存在适用项缺口 | 声明范围所需的参数或规则，在现有材料中尚未取得或明确。逐项记录缺口和影响。 |
| D 关键语义待核 | 来源版本、单位、时段映射或模型配对等关键问题影响整体解释。 |

等级按所查来源版本及 profile 判定。默认值需要注明已核读取规则及适用边界。适用范围待明确时标记待审。逐例说明应覆盖出力、平衡、常规与启停爬坡、最小开停时间、备用需求与交付、潮流与容量、冷热启动费用与切换规则、生产及空载和停机费用、初末边界以及适用的特殊资源和安全约束。原值、显式零、读取器默认、确有证据的简化、缺失、待核及不适用分别登记。求解、独立验解和再分发许可状态各自记录。

| `family` | 含义 |
| --- | --- |
| `network_uc` | 提供网络信息和 UC 规则，执行状态逐例登记。 |
| `network_uc_inputs` | 已整理的网络 UC 输入，执行和语义边界见对应 profile。 |
| `single_bus_uc` | 明确为单母线表示，例如 OR-LIB 三例。 |
| `system_aggregate_uc_inputs` | 机组参数与系统总负荷输入，当前资料未给出节点信息，例如邓俊2015六规模（继承Kazarlis基础参数）。 |

`case_count` 按索引实例计，`system_count` 按已识别的物理基础电网计。RPG IEEE24 两版与 openTEPES RTS24 在索引中记录为同一基础拓扑的不同数据版本。邓俊2015六例统一为一个文献家族，保留Kazarlis基础参数与后续文献补充的溯源；10台修改版与五个规模展开分别登记，不并列重复登记前后文献。独立日样本、规模变体和基础电网各按自己的口径统计。
