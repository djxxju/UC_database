# 本次10机组运行模型

计算profile：orlib10_audited_defaults_uc_v1。保留原JSON，不回写默认参数。公式依据SOURCES.md中固定UC.jl代码。仅实现本例平面数组、单档启动费用、单节点和零备用需求，不声称完整重建UC.jl软件或复现作者结果。

令u/v/w为开机/启动/停机二元变量，P为实际出力，C为生产费用，L为负荷削减。q=P-Pmin*u仅作为表达式。时段t=1,...,24，每时段1小时。

1. 目标 min sum(C + StartupCost*v) + 1000*sum(L)。罚价1000来自读取器默认值，并非原数据给定价格；正价削减与生产分开报告。
2. u_t-u_prev=v_t-w_t，v_t+w_t<=1。首时段u_prev按初始持续时间正负确定。
3. Pmin*u<=P<=Pmax*u。每个成本折点相邻段的斜率m与截距b约束C>=m*P+b*u；源曲线凸，因此最小化时得到原分段线性费用。离线C=0，不另加空载费用。
4. 初始剩余开/停时间锁定前max(0,min_time-abs(initial_status))小时。每t回看最小开机窗口的启动和<=u_t，最小停机窗口的停机和<=1-u_t。末端仅检查到24，不外延，不与第1小时循环。
5. t>=2：q_t-q_prev<=RU；q_prev-q_t<=RD。首时段仅初始在线机组检查q_1<=P0-Pmin+RU及q_1>=P0-Pmin-RD；初始离线不加该首时段爬坡式。
6. 源缺省SU/SD=1e6 MW，本例所有Pmax远小于此值，因此这些限额行冗余，可省略；不擅自设置为Pmin。
7. sum(P)+L=D，0<=L<=D。不添加超发松弛。实际报告sum(L)；只有削减为0时才称完整供应全部需求。
8. 原备用需求全0。固定备用提供量与缺额为0为可行等价选择：增加正备用只会占用出力余量并收紧爬坡，不可能改善p/u可行域或费用。本实现拒绝非零备用需求。

所有上述行由同一份neutral系数字典生成，两适配器使用同一模型SHA256。Gurobi和COPT单独构建与求解，无共享初始解。默认600秒、1线程、相对gap=1e-8、绝对gap=1e-7；具体参数、版本、代码/数据/模型哈希与日志均随实际运行保存。

验解不读取系数行：直接从源参数和候选u/v/w/P逐事件重算约束、逐段插值计算生产费用、启动费用与削负荷罚价，并核对求解器目标。检查完整性、有限数值、二元容差和残差，不以四舍五入掩盖不可行。

## 最终运行的紧凑成本表达

默认使用每机组每小时5个非负折点权重lambda：sum(lambda)=u，P=sum(X_k*lambda_k)，C=sum(Y_k*lambda_k)，将P/C表达式代回其余约束和目标。源曲线为凸分段线性，任意凸组合费用不低于同出力的曲线费用，而相邻两点可实现该费用；成本仅在最小化目标出现，所以与上文上图式在最优值和最优调度投影上等价，不需要SOS2。P/C在导出时重建并由独立插值验算。保留的非紧凑构建选项用于说明，不是本次最终提交求解器的表达。

最终规模1944变量、1696行，适配本机Gurobi受限许可。最终运行清单及两后端具有同一模型哈希。
